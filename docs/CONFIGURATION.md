# 通用配置与内容

默认只提供虚构示例，正式使用前由组织方替换内容与资料使用说明。界面支持中英文切换；工作人员后台目前为中文。

| 位置                                          | 可修改内容                                   |
| --------------------------------------------- | -------------------------------------------- |
| `shared/config.ts`                            | 工号位数与邮箱后缀，前端与后端共用规则       |
| `shared/programme.ts`                         | 示例专题、中英文名称、介绍与示例地点         |
| `shared/model.ts`                             | 新建活动使用的议程模板                       |
| `src/App.tsx`、`src/english.ts`、`index.html` | 页面品牌、双语介绍和资料使用文字             |
| 后台“规则与备份”                              | 组织方联系途径、保存期限、每人场数及取消规则 |
| 后台“培训管理”                                | 实际轮次、场次、日期、地点、容量和状态       |

默认 `employeeDigits: null` 兼容 v2 的 1–80 位工号，接受字母、数字、点、下划线和短横线，并以字母或数字开头；默认 `emailDomain: ""` 要求填写完整有效邮箱。

若所在组织明确统一规则，可以改成：

```ts
export const identityRules: {
  employeeDigits: number | null;
  emailDomain: string;
} = {
  employeeDigits: 8,
  emailDomain: "example.org",
};
```

随后重新构建并一起部署前后端。页面会显示八位数字提示及固定邮箱后缀，后端也执行同样规则。不同域名的完整邮箱被粘贴进来时会保留并报错，不会悄悄替换其后缀。工号以字符串保存，保留前导零。上述配置只验证格式，不验证身份或邮箱归属。

Preview 环境始终要求 `TEST-` 开头的虚构工号，并使用完整测试邮箱；自定义的正式规则在正式模式执行。更改规则不会自动修正旧数据，也不会破坏已经成功提交的原样重试。

`CANONICAL_ORIGIN` 是服务端环境变量。正式云环境缺失、格式错误或从另一域名访问时 API 会拒绝服务，防止新的部署别名成为第二个正式入口。开发机回环地址允许本机正式流程测试。此机制不改变旧部署的代码，旧版本入口仍需部署者自行退役或设置访问限制。

自定义后台输入的中文内容没有自动翻译服务。英文界面只翻译已知示例和界面文字；自定义场次标题可填写其英文字段，其他未知内容保持原文，避免猜译。日期与默认截止计算目前固定北京时间 `Asia/Shanghai`，没有宣称支持任意时区。
