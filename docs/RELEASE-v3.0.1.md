# v3.0.1 维护验证

日期：2026-10-13。范围：恢复可靠性、数据库就绪检查及公开发布保护。没有新增依赖或数据库迁移；现有完整 v3 数据库可直接升级代码。旧 v2 仍按 [升级指南](UPGRADE-v3.md) 完成全部迁移。

- 第一轮复现并修复大批量核对备份超过 D1 单条 SQL 限制、历史 NUL 字符影响恢复和未完成迁移却显示健康的问题。新业务文字拒绝异常控制字符，历史资料原样保留，旧口令仍可验证和更换。
- 第二轮用真实本机 D1 导入两次各 500 人核对的完整备份，逐字段比较业务表和大文本设置；中文、表情、换行、前导零、历史 NUL、审计记录和原报名凭证均保留。SQL 按字节分段，不删减核对依据。
- 恢复到新数据库时，指南和命令明确要求另设全新工作人员口令并验证旧口令失效。测试验证此流程；工具不会替管理员修改云端口令，仍须保留原 APP_SECRET。
- 公开检查覆盖暂存文件及本机已获取的全部可达 Git 历史，拒绝浅克隆。删除后的敏感形态、仅由标签引用的历史和 Git 替换对象均有反例检查；不能代替图片人工检查，也不覆盖未获取的远端或第三方克隆。
- 独立只读候选复查发现 Git 替换对象可能隐藏原始历史，已改为读取原始对象并加入回归。此次复查不是第三方安全认证。
- 类型、构建、完整测试套件通过，包括安全、网络、身份规则、旧版迁移、核对、双语及手机/桌面浏览器流程。锁定依赖的 `npm audit` 报告 0 个已知漏洞。

主分支发布流程要求 PR 和 GitHub Actions 的 `verify` 检查，管理员也适用，禁止强推和删除。此保护是托管仓库设置，克隆或 fork 不会自动继承，维护者须为自己的仓库另行配置。CI 仅在本机环境测试，不持有部署凭据，不上传测试数据。

上述检查不证明抵御无限流量攻击、真实身份真实性、校园网络可达性或组织数据治理已经解决。共享口令和免注册模式的边界保持不变。
