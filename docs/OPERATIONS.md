# 使用与运维

## 工作人员登录

网站下方的“工作人员入口”或 `/#staff` 可进入后台。首次使用部署方设置的 `ADMIN_PASSWORD`；本机体验时由 `npm run setup` 写入忽略的 `.dev.vars`。

当前为共享口令管理，登录有效期八小时。后台更换口令会撤销全部工作人员会话，退出登录会撤销当前会话。更换后的摘要存于数据库，优先于初始环境口令；仅更改云环境的 `ADMIN_PASSWORD` 不会覆盖后台已经设置的新口令。工作人员离岗时应更换共享口令。

若忘记已修改的口令，拥有数据库管理权限的部署者应先备份、暂停操作，再通过私有运维流程删除 `settings` 中的 `admin_password_digest` 项并清空 `admin_sessions`；之后以安全更新的环境 `ADMIN_PASSWORD` 登录。这是具有管理权限的恢复操作，不是公开网页功能，勿将数据库权限分发给报名者。

## 场次和名单

- 轮次与月份独立：改期可以跨月，场次仍属于原来的轮次；同一天可以有多场。
- 容量默认 36，后台允许 1–100000。下调至已报名人数以下会保留名单并停止新增，工作人员自行处理超额安排。
- 暂停、取消和归档都会停止新报名。取消活动保留原报名记录，工作人员可以导出受影响名单；恢复活动不会恢复个人主动取消的记录。
- 时间、地点、主题等重要变更，需检查影响人数和说明。已报名者在“我的报名”中看到变更提示并重新确认。**系统不自动发送通知**，复制通知后由组织方发布。
- 后台同时编辑同一条记录会提示冲突；重新加载，核对他人的最新修改后再操作。
- 工号按文本存储，前导零保留；全角字符和大小写按系统规则规范化。它用于去重，不验证身份。不要通过公开查询姓名或工号来找回凭证。
- XLSX 名单的文字单元格保护工号格式，并避免把用户输入当作表格公式。文件包含个人资料，仅在授权工作范围内传递。

## 备份与恢复

后台“规则与备份”选择“下载加密完整备份”，再次填写工作人员口令，并设置与工作人员口令不同的备份密码。浏览器加密并校验后下载 `.mentor-backup` 文件。文件含轮次、场次、报名、独立到场补记、核对结果、批次、设置与修改记录；不包含云密钥、后台口令摘要或工作人员登录会话。

密码和文件分开保管；忘记备份密码无法解密。原 `APP_SECRET` 必须另外保留，它参与去重和凭证校验。Excel 是供工作流转的普通名单，不是加密备份，也不能替代完整恢复材料。

[升级与恢复指南](UPGRADE-v3.md) 提供旧 JSON 和加密备份的恢复命令。工具在本机验证、生成仅供空库导入的 SQL，不会连接或覆盖云端数据库。SQL 输出含明文个人资料，必须私下保存。

恢复到新库前，必须设置全新的环境 `ADMIN_PASSWORD`，验证新口令可登录、旧初始口令和旧共享口令被拒绝后再开放服务。备份不含后台口令摘要，直接沿用原环境口令会使它重新有效。原 `APP_SECRET` 与 `DATA_SPACE` 则应保留，以维持旧记录和凭证。工具不会自动修改云端口令。

## 参会核对与导出

1. 打开“参会核对”，选日期和场次，对照签到表。
2. 勾选确认到场的人，点“标记已到场”，填写核对人和依据，确认保存。确实没来的人可以另外标记未到场；不确定的人保持待核对。
3. 没报名但确实到场的人，用“补录未报名到场人员”填写资料和确认依据。补记与报名分别保存，不倒填报名时间，不占已结束活动的报名名额。
4. Excel 已整理工号时，可粘贴工号列快速勾选，再人工确认。保存发生冲突先刷新核对；断网时点“核实上次保存结果”，避免重复操作。
5. “导出本场总名单”提供单场名单及当前核对状态。“学期汇总导出”按所选场次汇总不同老师的报名、已到场、未到场、待核对次数，并保留逐场明细。报名次数不等于实际出席次数。

工作人员“补报名”用于尚未结束活动的临时安排，需登记人和依据，仍受容量、同场去重、场次状态与版本限制。已结束活动使用到场补记。更改工号、依据或活动时间后，核对页面会提示需要重审的关联结果；不要用姓名相似来推断同一个人。

## 联系邮箱与日历

名单界面可按场次整理去重邮箱、复制密送收件人和编辑邮件草稿。实际邮件仍由工作人员在自己的邮箱发送。日历文件是 `.ics` 下载，由参加者自行导入 Outlook 等日历；不是自动接入其账户，后续改期也不会自动更新已导入的副本。

## 监测与交接

记录部署版本、数据库名称、负责人、联系方式、备份时间和下一次清理日期，密钥单独保管。定期检查可用性、账号用量和备份可恢复性。`/api/health` 只验证基础配置和结构，不等同于完整服务验收。

当前审计能追踪修改前后内容，但共享口令无法区分是哪位工作人员操作。需要个人责任追踪时，应先实现个人账户、权限和审计主体；本版本未提供这些功能。
